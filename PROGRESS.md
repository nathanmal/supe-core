# Progress Log — supe-core

Compressed history for Claude (and future-you) to reference across sessions. Entries are dated, newest first, terse — this is a state snapshot, not a changelog; `git log` is authoritative for that once this is under version control. Update whenever a session makes a meaningful change here, and prune/collapse old entries once they're no longer load-bearing context.

**Status:** Stable. Unit tests (68) cover the boot-order-critical pieces and the admin shell; the Feature suite runs against the local `supe_phpunit` DB.

- **2026-11-23** — More shared controls for supe-media's Media Library page. `AdminUi::subsectionStart()` gained `$collapsible`/`$open` (native `<details>`; a header action moves into the body, since `<summary>` can't hold controls; a closer stack keeps nesting right) and `AdminUi::iconButton()`. `AbstractSettingsPage` reads `supe_collapsible` on child sections. `SettingsField` gained `text`, the editable `table` (columns text/number/toggle; per-row `_locked`/`_display`/`_removable`; `addable` with a `<template>` row), and `name`/`aria_label` args. New `assets/admin.js` (table add/remove; enqueued with the CSS by `AdminAssets`, deferred, in footer). Checked radios/checkboxes use the Supe accent instead of WordPress's admin color scheme. Unit tests 63 → 68. Checked via headless render (collapse, add row, header toggle undimming).
- **2026-11-23** — Settings controls for module settings pages (decided with the user: built in core, first used by supe-media's Image Settings). `AdminUi::cardStart()` gained an optional `SafeHtml $action` header slot; new `AdminUi::subsectionStart()/subsectionEnd()`. `AbstractSettingsPage` reads `supe_parent` (child sections render as sub-sections in the parent card; orphans still render as cards), `supe_description`, `supe_icon`, `supe_action` from section args. New `Support\SettingsField` (toggle switch, number with unit, radio group with per-choice descriptions; `render()` is the `add_settings_field()` callback). CSS: toggle, input-group, choices, sub-sections, and `:has()` dimming of a card/sub-section body while its header toggle is off. Editable table/repeater not built yet (comes with supe-media's thumbnail sizes editor). Unit tests 53 → 63; supe-editor unit suite still green. Visual check: headless render of the media page; header toggle + sub-section toggles not yet seen in a browser (no consumer yet).
- **2026-11-23** — Admin CSS now loads as a real file, not inline. Promoted `supe-editor`'s `Module::mapSymlinkedInstall()` into `Support\PackageAssets` (package name + root dir; `register()` maps the Composer install path to the real path in `$wp_plugin_paths`; `url()`, `path()`, `version()` (filemtime), `rootFile()`). `AdminAssets` enqueues `assets/admin.css` via `PackageAssets` (deps `dashicons`, version = mtime) on Supe screens only. supe-editor switched over (binds `supe.editor.package`, registers in `boot()`). Verified on supe.test with WP-CLI: URL `/wp-content/plugins/supe/vendor/nathanmal/supe-core/assets/admin.css` (200, text/css), enqueued on `page=supe-media`, not on other screens, editor block asset URLs unchanged. Verified in a logged-in browser session as `claude` (Playwright): Overview, Blocks and Media Library pages all render the shell with the stylesheet linked, no inline styles. Ecosystem linkage: ecosystem rules moved to `../supe/SUPE.md`, which every package's `CLAUDE.md` imports (`../supe/CLAUDE.md` is now plugin-specific); added this package's `CLAUDE.md` (flow-down/flow-up checklists) and "Promotion candidates" in `ROADMAP.md`. Pre-commit tidy: `tests/wp-tests-config.sample.php` defaulted to `supe_test` (the dev site's DB, which a Feature run would wipe), now `supe_phpunit`; Feature suite run for the first time (passes). README `stats()` signature corrected. Unit tests 47 → 53.
- **2026-11-23** — Shared admin look & feel (user's call: "hero header + cards" direction; migrate the active modules in the same change). `AbstractAdminPage::render()` is now concrete. It returns nothing without `capability()`, otherwise outputs a branded shell: a gradient hero (inline SVG Supe mark, title, optional `description()` / `version()` pill), a tab bar for the page's menu family via the new `AdminMenuRegistry::familyOf()` (capability-filtered, labelled by `tabTitle()`), `<hr class="wp-header-end">` so WP notices land below the hero, then `renderContent()`. `render()` is no longer abstract, so pages that override it (incl. paused modules' pages) still work but skip the shell. The registry now caches one instance per page. New `Support\AdminUi` helpers (card / stats / table / badge / code / emptyState / notice, all escaping; cells may be `Support\SafeHtml`), `Support\AbstractSettingsPage` (Settings API sections as cards, sticky save bar, calls `settings_errors()` off the Settings menu), `Admin\AdminAssets` (inlines `assets/admin.css` via `wp_add_inline_style` only when `$_GET['page']` is a registered Supe page; inline because a vendored library has no reliable URL), and `Core::VERSION`. DashboardPage rebuilt with stat tiles and a modules table; its tab is "Overview" while the sidebar keeps "Supe". Unit tests 24 → 47. README "Shared look & feel" section and stub updated. Visual check via headless-Chrome render of the Dashboard and media Settings pages with stubbed WP; not yet viewed in a live wp-admin.
- **2026-09-06** — Added `Admin\DashboardPage`: a shared top-level "Supe" admin menu (slug `supe`), registered by `Core` itself in its constructor (via `$adminMenuRegistry->addPage()`) before any module boots, so every module's own page can attach under it as a submenu by returning `DashboardPage::slug()` from `parentSlug()` instead of scattering into Settings/Media/etc. `render()` lists currently-loaded modules via `Core::getInstance()->getRegistry()->getLoadedModules()`. Updated the four sibling packages' pages (`supe-blocks`, `supe-email`, `supe-media`, `supe-security`) to nest under it instead of `options-general.php`. 3 new Unit tests (`DashboardPageTest`) plus a `CoreTest` assertion that the page is registered on construction; README's "Building an Admin Page" section and `stubs/ExampleAdminPage.php` updated to demonstrate attaching to the shared menu.
- **2026-09-06** — Added a shared admin menu/page system: `Contracts\AdminPageInterface`, `Support\AbstractAdminPage` (defaults for everything but `slug()`/`pageTitle()`/`render()`, plus a `view()` template helper), `Admin\AdminMenuRegistry` (collects pages, adds them to WordPress on `admin_menu`, top-level before submenu), and `Exceptions\InvalidAdminPageException`. `Core` now owns one `AdminMenuRegistry` instance (mirrors how it owns `ModuleRegistry`) and binds it into the container so `AbstractModule::addAdminPage()` can reach it. Deliberately placed in `supe-core` rather than a new sibling package — user's explicit call after being shown the tradeoff (ROADMAP.md's "stay minimal" note vs. every module needing one shared registry instance, which a separate optional package can't guarantee). 8 new Unit tests (`AdminMenuRegistryTest`, `AbstractAdminPageTest`); `stubs/ExampleAdminPage.php` added and wired into `stubs/ExampleModule.php`'s `boot()`; README's "Building a Module" section gained a "Building an Admin Page" sibling and two new hook rows (`supe/admin_page_registered`, `supe/admin_page_added`).
- **2026-09-05** — Extracted from the `supe` plugin as its own Composer package (`nathanmal/supe-core`, type `library`). Contains `Core` (formerly `Loader` — renamed per request), `Registry\ModuleRegistry`/`ModuleCandidate`, `Support\Container`/`AbstractModule`, `Contracts\ModuleInterface`, `Exceptions\*`, the global `supe()` helper (now in `src/functions.php`, autoloaded via Composer `files`), and `stubs/ExampleModule.php`. Namespace stayed `Nathanmal\Supe\*` at first — only the package/repo split, not the API (see the later namespace-remap entry below).
- **2026-09-05** — Remapped the package namespace from `Nathanmal\Supe\*` to `Supe\Core\*` (e.g. `Supe\Core\Core`, `Supe\Core\Registry\ModuleRegistry`), so the namespace root matches the package name (`nathanmal/supe-core`) the same way every module's does (`Supe\Blocks\*` for `nathanmal/supe-blocks`, etc.). Updated across every dependent package (`module-bootstrap.php`, `src/Supe{Name}.php`, `tests/bootstrap-feature.php`, Feature boot tests) and `composer.json`'s `psr-4`/`autoload-dev` maps. All 29 Unit tests re-verified passing after the remap.
- **2026-09-05** — Updated `README.md`'s "Building a Module" scaffold and `stubs/ExampleModule.php` to reflect the ecosystem's current conventions: `bootstrap.php` (not `module-bootstrap.php`) as the Composer `"files"` entry point, and every in-namespace module naming its main class `Module` (third-party example classes outside `Supe\*` can still use any name, as `ExampleModule.php`'s `GalleryModule` does). Also added the previously-missing `function_exists('add_action')` guard to both the README scaffold and `ExampleModule.php`'s docblock example, matching the real pattern used by every actual module.
- **2026-09-05** — **Bug fix:** `Exceptions/SupeException.php` bundled `SupeException`, `InvalidModuleException`, and `ContainerException` in one file. PSR-4 only autoloads a class from a file matching its own name, so `InvalidModuleException`/`ContainerException` silently failed to autoload whenever an actual error path ran (dormant bug — never hit on a normal successful boot). Split into three files matching their class names. (See `../supe/CLAUDE.md`'s "PSR-4 and Autoload Discipline" section — the same pattern recurred in `supe-email` and `supe-security`.)
- **2026-09-05** — Added the full Unit/Feature PHPUnit scaffold (`brain/monkey` + `yoast/wp-test-utils` + `wp-phpunit`). 12 Unit tests passing (`ContainerTest`, `ModuleRegistryTest`, `CoreTest`). `tests/Feature/CoreBootTest.php` written but not yet run against a real DB.
